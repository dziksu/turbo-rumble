# Review i refaktor — 21.10.2026

Zakres: istniejący prototyp Turbo Rumble, klient Three.js, symulacja Rapier, Socket.IO, SQLite i przygotowanie Docker/Coolify. Aplikacja była już w TypeScript; zmiana wzmacnia istniejący kod i usuwa słabe granice modułów. Zachowano mapę i parametry prowadzenia. Nie wykonywano wdrożenia produkcyjnego.

## Świadomie pozostawione granice

- Jedna replika i pamięciowe pokoje. Restart nie odtwarza meczu; przed skalowaniem trzeba zaprojektować przydział pokoi i własność światów fizyki. Sama zmiana adaptera Socket.IO nie wystarczy.
- Brak benchmarku dziesiątek równoległych pokoi i realnych telefonów w sieci komórkowej w ramach tego refaktoru. Testy sieciowe używają lokalnych klientów Socket.IO.
- Ranking to zapis wyników, bez systemu kont. Obecny refaktor nie dodaje trwałej tożsamości ani panelu administracyjnego.
- Nie zmieniano parametrów jazdy, uzbrojenia ani ostatnio poprawionego układu wyników. Rozdział systemu broni zachowuje istniejące wejścia testowe `Race`.
- Rapier emituje ostrzeżenie inicjalizacji w swojej paczce kompatybilności; istniejące testy przechodzą. Nie wyciszano go globalnie ani nie zmieniano silnika fizyki w ramach porządkowania kodu.

## Weryfikacja

Bazowy zestaw: 62 testy. Po refaktorze: 69 testów, w tym walidacja konfiguracji/protokołu, ograniczenie faz, monotoniczność wejścia, SQLite/backup, prawdziwe HTTP/WebSocket, poprawne zamykanie i własność zasobów GPU. Testy sieciowe wymagają środowiska pozwalającego otwierać lokalne porty.

Odbiór obrazu i wyniki pełnego playtestu zapisano w bieżącym raporcie `docs/qa/refactor-deployment.json`. `npm audit --omit=dev` podczas tego przeglądu: 0 zgłoszonych podatności. Jest to wynik bieżącej bazy advisory, a nie gwarancja bezpieczeństwa.

Obraz lokalny linux/arm64: health `healthy`, UID 1000, Node 24.22.1, bez Vite/TypeScript/ESLint w runtime. Pełny mecz ośmiu klientów: 73 sprawdzenia (łącznie z użyciami broni), wszystkie pięć przedmiotów, 20 eliminacji, zapis dokładnie raz i rewanż. Backup: integralność `ok`; dwa zakończone wyniki pozostały identyczne po usunięciu kontenera i utworzeniu nowego z tym samym volume. SIGTERM zakończył proces z kodem 0. Finalny smoke przeszedł również po odtworzeniu. Przygotowano CI linux/amd64, ale zdalny workflow GitHub nie był tu uruchamiany.
